五、修复过程中新发现并处置的 4 个缺陷（审查报告之外）

★ 1. beauty.html 话术库全部 CRUD 按钮 ReferenceError（实战级功能瘫痪）

  • 现象：真实浏览器探针实测 window.saveScriptLib === undefined（页面加载后）。
  • 根因：补丁把 window.copyScriptById / editScriptLib / deleteScriptLib / saveScriptLib 的 EXPORTS 块嵌进了 `copyScriptById` 函数体内部，且 copyScriptById 自身从未挂到 window → 四个入口一个都不存在，点按钮即 ReferenceError。
  • 排查手段：花括号配平不可靠（模板字符串干扰）→ 改用 AST（acorn）作出权威判定。
  • 改法：EXPORTS 迁到顶层（const insertEmotionResponse 之前，所有 const 声明之后）；_apply_scriptlib_guard_20260921.py 的锚点同步迁移。21/21 回归验证 CRUD 已挂载。

★ 2. 构建链「互踩」：单一来源同步 vs 图片外置，导致整链在第 5 步硬停

  • 现象：_build_all.py build 在第 5 步 _sync_dache.py --check 硬停：quiz.html 与单一来源不一致。
  • 根因：_sync_dache.py（构建第 5 步）把 __DACHE_IMG_*__ 占位符替换为 内联 data URI；而 _extract_inline_images_20260921.py（第 20 步）又把这些大图抽成 assets/img/*。两者互为逆操作 → 每轮构建必留漂移。此前只能「手工跑 _sync_dache.py 绕开」，漂移每轮复现（大撤 4 张长图共 2.07MB）。
  • 改法：让 _sync_dache.py 直接产出已外置形态：assets/img/<md5(base64)[:8]>.jpg（与抽取器同口径，内容寻址、按需落盘、幂等）。现在 check 稳定通过、抽取器无事可做。
  • 验证：_sync_dache.py --check → qa.html / quiz.html 双 UP-TO-DATE；四张长图 md5 对应关系实测 85893b92 / 8a07c3fe / c3640803 / 68d6307b 全部命中。

★ 3. APK 装配自检判据过期 → 明明正常也报 [FAIL]

  • 现象：_apply_apk_fix_20260918b.py（v3）自检 [FAIL] v2 预热收敛保留。
  • 根因：v2 的自检判据早已随壳层「预取门控」改为 ('APK_PREWARM_V2' in out) or ('function _pwEnv' in out)，但 v3 的同名判据没跟着改，仍只看 APK_PREWARM_V2。产物实际含 _pwEnv，功能正常。
  • 改法：v3 判据与 v2 对齐。复跑后 28 项自检全 OK。
  • 风险提示：该 FAIL 出现在装配链末端，若被忽略会掩盖真正的 A 阶段失败（A 阶段失败时 www 不更新、APK 字节数与旧包完全相同，极易误判为「打包成功」）。

★ 4. APK / PWA 内 index.html 仍带明文口令

  • 改法：由 APK 重装配 + PWA 重建自动修复（源头是已修复的 _shell_enhance.js）。现将 4 份产物纳入 _verify_pwd_hash_20260922.js 的强断言，再出现即失败。
