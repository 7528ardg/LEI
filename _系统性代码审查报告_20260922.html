一、总体评价

项目整体工程质量中上：安全红线（源码零内置 AI 密钥）成立，AI 渲染主链路有转义保护，Python 构建链无 shell=True/rmtree 等危险调用，幂等注入机制健全，绩效敏感数据有 AES-GCM 加密。但存在 1 个确凿的存储型 XSS（可被跨用户触发）、凭据管理整体薄弱（管理员口令硬编码 + 用户口令明文落盘）、构建维护脚本两处非原子写可截断关键文件、qa 聊天渲染长会话 O(n²) 内存泄漏。

  • 高危 3 项 ｜ 中危 11 项 ｜ 低危 16 项（合并后）
  • 最优先：修复 beauty.html 存储型 XSS（P0）

二、高危问题（3 项）

H1. beauty.html 存储型 XSS —— 话术标签与表单回填未转义

  • 位置：beauty.html:29773（${tag} 直接拼接）、29816（textarea 回填 ${state.scriptLibFormContent}）、29819（value 属性回填 ${state.scriptLibFormTags.join(',')}）
  • 影响：tags 由用户在新增表单录入（31888），且脚本库可经 kb-admin 导入，属存储型 XSS、可跨用户触发。构造 </textarea><img src=x onerror=...> 或含 " 的属性逃逸即可执行任意脚本，进而读取 localStorage 中的用户口令、AI Key 等全部数据
  • 触发条件：录入/导入含恶意标签的话术 → 打开话术库列表或编辑表单即触发
  • 佐证：话术正文渲染经 slRender→esc（879）是安全的，问题恰在"正文以外"的三个拼接点
  • 修复：三处统一走 esc()/escHtml()；textarea 回填改用 textContent 赋值；新增回归断言（可挂 _verify_scriptlib_guard.js）

H2. qa.html 聊天渲染全量重建 + 消息数组无上限 —— 内存泄漏与 O(n²) 卡顿

  • 位置：qa.html:7167（wrap.innerHTML = chat.msgs.map(...)）、6799 / 9988 / 10020（msgs 只增不减，无容量上限）
  • 影响：长会话下 ① chat.msgs 无限增长（含大段 HTML/天气卡）→ 内存持续泄漏；② 每条新消息重建全部气泡并重跑 qaWrapBetterAnswer/qaFbBar（7170-7171）→ 单条 O(n)、整体 O(n²)，数百条消息后明显掉帧甚至页面卡死
  • 触发条件：单会话累计数百条问答（培训/练习场景极易达到）
  • 修复：chat.msgs 设上限滚动裁剪（如保留最近 200 条）；renderChat 改增量 append 新节点而非全量重写

H3. _sync_shell_js.py 非原子写关键构建脚本 —— 中断可截断 _gzip_build.py / _build_4in1.py

  • 位置：_sync_shell_js.py:27-30（write() 直接 io.open(p,'w').write(s) 覆盖写）；且模块顶层执行、无 __main__ 守卫
  • 影响：违背项目"落盘原子写"铁律。Ctrl-C / 进程被 kill / 磁盘满时，两个核心构建脚本被截成半截，整条构建链崩溃且不易察觉（下次跑链才爆）
  • 触发条件：同步执行期间中断
  • 修复：改 .tmp_write + os.replace；补 if __name__=='__main__': 守卫；删除 28 行死代码 s.encode('utf-8')

安全类

  2. qa.html:2776/10437/13635、quiz.html:10981、risk-lite.html:17958 window.open 未带 noopener
  3. risk-lite.html:21384 new Function('event', code) 转换 onclick 属性 —— 当前 code 来自开发者属性，若未来 innerHTML 注入外部 onclick 即升级为代码执行

  5. index.html:1814 app_base_url 可由 localStorage 覆盖为任意镜像基址 —— XSS 后可重定向模块加载，建议白名单校验

  7. qa.html:2533/2719 用户自带 AI Key 明文存 localStorage（设计内），建议界面提示风险

  5. _build_hosted.py:139 shutil.copyfile 等非原子产物写（重跑可覆盖，危害低）

五、各维度"未发现问题"清单（负向结论，同样重要）

  • 硬编码 AI 密钥：未发现。_3d_token.txt 未被任何生产代码引用/打入产物；__QA_BUILTIN_AI__ 在构建链中不被赋值，"源码零内置密钥"红线成立
  • AI 回答渲染 XSS：qa mdToHtml（8664）先 esc() 再生成 HTML、用户问句 addMsg(esc(q))，安全；beauty 竞品渲染 escHtml（32207）已有修复记录
  • 动态代码执行：无 eval(用户输入) / setTimeout(字符串)
  • Python 危险调用：无 shell=True / os.system / shutil.rmtree / eval；subprocess 均列表形式
  • 幂等注入：未发现 strip 不净 / 重复注入 / 漏匹配；各大标记块（CC_AI_COMPANION_v1 等）幂等守卫齐全
  • 嵌入态/首屏约定：max-height !important、MutationObserver 防重绑、QA_SHOW_WELCOME=false、常问条不自动显示，均符合
  • 正则注入：用户输入未进入 RegExp 构造器；唯一 new RegExp（beauty 31103）来自静态关键词表
  • 绩效数据安全：AES-GCM 加密落 IndexedDB，localStorage 仅存密文，密钥管理得当（正向实践）
