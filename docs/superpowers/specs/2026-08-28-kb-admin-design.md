# 手册知识库管理板块（kb-admin）设计

* 日期：2026-08-28

* 状态：已确认

* 关联：路径 A「内部创新立项」首个可演示功能点；qa.html 四库知识体系的管理端

## 1. 背景与目标

现有四库（CCM 256 / MGM 135 / SVC 66 / Daily 32，共 489 条）的知识由人工对照手册原文整理，手册更新时需手工比对、手工清洗，低效且易漏。本板块把这条链路自动化：**上传新版手册 → 自动解析 → 与知识库匹配 → 人工确认 → 更新知识库 → 查漏补缺**，形成"手册数字化维护工作台"，同时作为内部创新立项的核心演示。

目标用户：管理员本人（乘务员端不可见管理细节，仅消费更新后的知识）。

## 2. 决策记录（用户已拍板）

| 决策点       | 结论                               |
| --------- | -------------------------------- |
| 使用场景      | 管理员维护工具                          |
| 上传格式      | PDF（浏览器端 pdf.js 解析）              |
| 候选问题/答案生成 | 离线规则检测为主 + 可选 SpringAI 生成候选（可切换） |
| 落库方式      | 本机 localStorage 覆盖层 + 可导出增量更新包   |
| 实现方案      | 独立第 10 模块 kb-admin.html（方案 A）    |

## 3. 架构总览

### 3.1 模块位置与依赖

* 新增 `kb-admin.html`（第 10 个模块）。

* 三处外壳（`index.html` / `_build_4in1.py` / `_gzip_build.py`）各加「📇 库管理」页签 + `EMBED_CSS` 条目 + SOURCES 映射。

* pdf.js：开发期引用 `libs/pdf.min.js` + `libs/pdf.worker.min.js`；构建脚本按 `inline_risk_deps` 同款方式内联，worker 用 Blob URL 方式内联（`GlobalWorkerOptions.workerSrc = URL.createObjectURL(...)`），保证离线单文件版可用。

* `qa.html` 增加约 20 行覆盖层合并逻辑（只读接管，不改四库源数据）。

* AI 能力复用 SpringAI 客户端配置（`localStorage['spring_ai_cfg']`），与 qa/beauty 同一套 Key。

### 3.2 核心数据流

```
上传 PDF → pdf.js getTextContent 逐页提取 + ===PAGE N=== 页标记
  → 预检（页数/字符数/每页文字密度；疑扫描件提示 OCR）
  → 章节结构解析（正则识别 "3.1.2.1 标题" 层级）
  → 与四库条目匹配（src 前缀 + 章节标题关键词 + t 标签 三路加权）
  → 覆盖率地图（每库：已覆盖✅ / 新增 / 变更 / 缺口）
  → 差异化清单（人工审核界面）
      ├ 新增 → 候选条目模板（可切 AI 生成）
      ├ 变更 → 旧条目对原文，标"待复核"
      └ 已覆盖 → 跳过
  → 确认入库 → localStorage['kb_overlay_v1'] + 导出增量更新包
  → qa.html 启动时合并覆盖层 → 乘务员端即时生效
```

## 4. 功能规格

### 4.1 PDF 上传与解析

* 仅接受 PDF；文件可多选但同批同库（上传时选择目标知识库：CCM/MGM/SVC/Daily）。

* 解析用 `pdfjsLib.getDocument`,逐页 `page.getTextContent()`,拼接纯文本,每页插入 `===PAGE N===` 标记(与手册原始解析工作流一致)。

* 预检：页数、总字符数、每页平均文字密度。密度低于阈值（每页 <80 字符）判为疑似扫描件/图片 PDF，阻止进入解析并提示「请先 OCR 或提供文字版 PDF」。

* 解析失败（pdf.js 缺库 / worker 不可用 / 文件损坏）：明确报错文案 + 引导，禁止静默空白。

### 4.2 章节结构解析

* 正则识别章节标题行：编号形如 `3.1.2.1`、`3.1`、`4.2.3`，后跟中文标题（标题不含句号/数字密集行除外）。

* 构建章节树（级联层级），每个章节保留：全编号、标题、起始页（`===PAGE N===` 就近）、正文文本块。

* 章节标题与页码同时作为匹配与覆盖率地图的输入。

### 4.3 匹配与覆盖率地图

* 三路加权匹配：

  1. **src 前缀**：KB 条目 `src`（如 `CCM 3.1.2.1` / `服务规范 2.2.1`）与章节编号前缀对齐（权重最高）；
  2. **章节标题关键词**：条目分类 cat 与章节标题名词重叠；
  3. **t 标签**：条目标签 `t` 与章节正文高频词重叠。

* 输出每个库的章节覆盖状态：`已覆盖` / `新增`（KB 无对应条目）/ `变更`（src 相同但新旧正文差异显著，以字符重叠率文本相似度阈值判定）/ `缺口`（原 src 引用章节在新手册中消失或章节存在但无条目）。

* 覆盖率地图是"待补任务量"的直观呈现，可作为立项演示页。

### 4.4 差异化清单与人工审核

* 每条差异以卡片/表格呈现：状态标记、章节号、标题、正文摘录、匹配到的旧条目（若有）。

* 「新增」条目提供候选模板：`{cat 取自章节树分类映射, icon 自动, src=章节全编号, t 标签候选, q 待填, a 章节正文摘录}`，管理员补写 q/a 后勾选入库。

* 「变更」条目并排展示旧答案与新原文，管理员选择「保留旧条目 / 改用新原文 / 修订后保留」，操作后状态为"待复核" → 确认后写入覆盖层。

* 支持批量勾选确认与逐条编辑。

### 4.5 AI 候选生成（可切换）

* 复用 `spring_ai_cfg`；未配置或调用失败自动回退离线模式（沿用现有降级约定）。

* 对选中的新章节文本调用 SpringAI 生成 `{q, t, cat}` 候选（a 默认取手册原文摘录，不替代正文）。

* 强制 few-shot + 输出约束（单轮产出、JSON 结构、仅起草不当事实），沿用记忆中的 glm-4-flash 防跑偏经验。

* 生成结果标「AI 候选」标记进入审核列表，人工确认后入库；不直接改写手册正文。

### 4.6 存量扫描 / 体检（不传文件也可用）

扫描现有四库，输出「知识库健康度体检报告」：

1. 分库分章条目统计，章节条目为 0 = 裸缺口；
2. 答案 `a` 中出现「以手册原文为准 / 详见原文 / 以…为准」等弱覆盖标注的条目 = 已知待补清单（SVC 库已存在此类信号）；
3. `t` 标签质量问题：缺失/过短（单字）/ 与已有标签重复度高；
4. 同一 `src` 多条目（部分库规范要求一源一条，此处仅提示，不判错）。
   报告可导出 Markdown，作为立项汇报素材。

### 4.7 覆盖层合并（qa.html 约 20 行）

* kb-admin 写入 `localStorage['kb_overlay_v1']`，schema 见 §6（`byLib` 内条目带 `_op:'add'|'mod'` 标记）。

* qa.html 在四库 `window.KB_*_RAW` 定义之后、搜索逻辑之前执行合并：

  * `_op:'add'` 按库 append；

  * `_op:'mod'` 按 `src` 精确匹配替换原条目（带签名校验，防损坏数据）。

* 合并逻辑失败必须静默降级（沿用原库），不影响乘务员端任何现有功能。

### 4.8 增量更新包导出 / 导入

* 「导出增量包」：生成带 `magic + version` 头的 JSON（沿用全局备份签名体系），内容与覆盖层一致，可存网盘/传输至其他设备；

* 「导入增量包」：校验签名后写入覆盖层，日志提示导入条目数；

* 同时提供「复制为 JS 片段」按钮：输出 `window.KB_*_RAW` 可直接粘贴追加的代码片段，便于正式回写 `docs/_kb_*.js` 源文件后重建（与既有"改 qa.html 后同步 docs 源文件 + 重建"纪律衔接）。

## 5. UI 分层（kb-admin.html）

* 顶部状态条：四库概要（各库条目数/覆盖数/缺口数）+「体检」入口 +「AI 候选」开关。

* 主 Tab：

  1. **上传解析**：文件选择 → 预检进度 → 解析结果（页数/章节数）；
  2. **覆盖率地图**：按库折叠的章节网格，色标四状态 + 图例；
  3. **差异审核**：差异清单表格（状态/章节/标题/操作），批量确认；
  4. **体检报告**：存量扫描结果 + 导出 Markdown；
  5. **覆盖层管理**：当前覆盖层条目列表、导出/导入/清空、复制 JS 片段。

* 模块自带顶栏在嵌入外壳时由 EMBED\_CSS 隐藏（沿用现有模式）。

## 6. 数据格式

条目字段（沿用四库现有 schema）：

```js
{ cat:'分类', icon:'📘', src:'CCM 3.1.2.1', t:['标签'], q:'问题', a:'HTML 答案' }
```

覆盖层 schema：

```json
{
  "magic": "kb-overlay-v1",
  "version": 1,
  "updatedAt": "ISO时间",
  "byLib": { "ccm": [条目…], "mgm": [条目…], "svc": [条目…], "daily": [条目…] }
}
```

* `byLib` 内条目含 `_op:'add'|'mod'` 标记；`add` 直接 append，`mod` 按 `src` 精确替换。

* 增量更新包 = 上述对象整体（含 magic/version）。

## 7. 错误处理与边界

| 场景              | 行为                                 |
| --------------- | ---------------------------------- |
| 扫描件/文字密度低       | 拦截并提示先 OCR；绝不静默解析                  |
| pdf.js 加载失败     | 明确错误 + 重试/下载引导，不白屏                 |
| 覆盖层损坏/签名不符      | qa.html 静默忽略；kb-admin 提示"数据无效，已忽略" |
| localStorage 写满 | 逐条降级写入并计数提示                        |
| AI 未配置/调用失败     | 自动回退离线规则模式                         |
| 上传文件与四库完全覆盖     | 提示「无变更」直接结束，不产生差异条目                |
| 非 PDF           | 上传前拦截                              |

## 8. 构建与体积

* 新增 `libs/pdf.min.js`、`libs/pdf.worker.min.js`（pdfjs-dist legacy/UMD 构建），放项目 `libs/`。

* `_build_4in1.py` / `_gzip_build.py`：kb-admin 条目走 `inline_risk_deps` 同款内联流程（把两个库内联为 `<script>` 块 + Blob worker），再 gzip。

* gzip 后离线完整版预估 +1\~1.5MB（5.07MB → 约 6.2MB 量级），可接受。

* 外壳 EMBED\_CSS 增加 `kbadmin` 条目。

## 9. 测试计划

1. **kb-admin.html（mock 驱动）**：构造迷你手册文本（含编号章节与干扰行），验证章节树解析、覆盖率地图、差异清单正确性；构造覆盖层 mock 验证审核→入库→导出链路。
2. **AI 候选（mock 返回）**：验证候选条目展示、审核后入库、失败降级。
3. **qa.html 合并逻辑（node）**：覆盖层存在/缺失/损坏三态，确认合并结果与静默降级。
4. **构建回归**：三套外壳语法 `_check_js.py` + node --check；单文件版体积与离线解压校验（沿用现有 verify 脚本）。
5. **存量体检**：对现有四库跑体检，核对报告条目数与既有知识一致。

## 10. 范围（明确不做）

* 不做文档在线编辑（手册原文编辑仍走源文件）。

* 不做全员可见的管理入口（乘务员端无管理 UI）。

* 不做 PDF 渲染/批注（仅提取文本）。

* 不做自动发布到 GitHub Pages（仍由人工确认后构建/提交）。

## 11. 里程碑拆分（建议实施顺序）

1. kb-admin.html 骨架 + 外壳页签 + pdf.js 内联（静态可用）
2. PDF 解析 + 章节树 → 覆盖率地图
3. 差异化清单 + 审核入库 → 覆盖层 + 增量包
4. 存量体检扫描
5. AI 候选生成（可切换）
6. qa.html 覆盖层合并 + 全链路构建回归
