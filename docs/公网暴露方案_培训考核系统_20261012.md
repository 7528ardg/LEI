# 局域网服务公网暴露 · 完整落地方案

> 目标服务：客舱小助手 + 培训考核系统（单端口同源，Flask，`exam_system/app/app.py`）
> 编写日期：2026-10-12　适用场景：家用／小型办公网络、个人自建服务

---

## 0. 先看环境实测结论（决定了选型，不是猜测）

| 项目 | 实测值 | 说明 |
| --- | --- | --- |
| 本机内网地址 | `10.20.30.40/24` | 网卡 示例有线网卡 + Wi-Fi |
| 默认网关 | `10.20.30.1`，另有 IPv6 链路本地网关 `fe80::1%14` | 单位/园区网关，**路由器不在你手里** |
| 出口公网 IP（IPv4） | `203.0.113.55`，AS64500（示例运营商） | **与另外成千上万用户共享** → 典型 CGNAT |
| 出口 IPv6 | `2408:8256:…`（联通） | 有 IPv6，但单位通常防火墙默认拦入站 |
| 服务监听 | `0.0.0.0:8000` LISTENING（PID 16460） | 已满足「监听全部网卡」，无需改 |
| 本机可用隧道工具 | 仅 `ssh`（无 frpc / cloudflared / ngrok） | 走 SSH 隧道 or 先装工具 |

**由此得出的硬结论：**

1. **本机没有独立公网 IPv4**。`203.0.113.55` 是运营商级 NAT 出口，你在路由器上做端口映射也没有用——外网根本到不了你的路由器。
2. **路由器管理权限不在你手上**。网关是单位设备（DNS 搜索域 `smartont.net`），即使有公网 IP 也改不了映射规则。
3. 因此，**方案 ①「公网 IP + 端口映射」在本机不可行**，唯一出路是**主动向外建立隧道**（由内向外拨号，绕过 CGNAT 的入站限制）。

> 若这台机器换到**你自己控制的家用路由器**（电信/联通拨号、光猫桥接、路由器可登录）后面，且拿到独立公网 IP，方案 ① 才成立——本文档一并给出该分支的配置。

# 第一部分 · 配置项清单

## 1.1 方案对比（选型依据）

| 方案 | 原理 | 适用场景 | 成本 | 优点 | 缺点 | 本机可用性 |
| --- | --- | --- | --- | --- | --- | --- |
| **① 公网 IP + 端口映射** | 路由器把公网 `:8000` 转发到 `192.168.x.x:8000` | 有独立公网 IP + 路由器后台可登录 | 0 元 | 直连、最快、无第三方依赖 | **CGNAT 下完全失效**；80/443 常被运营商封；家宽 IP 常年变动 | ✗ CGNAT，路由器非我方 |
| **② 内网穿透客户端**（frp / 花生壳 / 向日葵远控） | 客户端主动连公网中转服务器，由中转反向回连本机端口 | 无公网 IP、要求「一条命令搞定」 | 免费～百元/年 | 部署快、固定公网入口 | 第三方服务器需信任；免费版常限速限流；花生壳等强制走已备案域名 | ✓ 推荐（需先下载客户端） |
| **③ SSH 反向隧道**（`ssh -R`） | 本机 ssh 到 VPS，主动在 VPS 上开一个监听端口映射回本机 | 有 22 端口可达的 VPS、愿意维护两台机器 | VPS ¥30-100/月 | 依赖极低（本机已装 `ssh`）；通道加密；无需装第三方客户端 | 需自己管 VPS；断线需守护重启；不自带 HTTPS | ✓ **本机当前唯一现成可用** |
| **④ 云服务器反向代理** | VPS 上跑 Nginx/Caddy，做 TLS 终止 + 限流 + 反向代理回本机 | 长期对外服务、要 HTTPS + 限流 + 日志审计 | VPS ¥30-100/月 + 域名 ¥50/年 | 能力最强：真证书、强制跳转、IP 白名单、限流、访问日志；本机零改动 | 需 VPS 与域名（大陆需备案）；链路多一跳 | ✓ **综合最优** |
| **⑤ Cloudflare Tunnel / Tailscale 等 SaaS 隧道** | 客户端出站连 SaaS，由其边缘反向代理 | 图省事、可接受 SaaS 依赖 | 免费～$5/月 | 零配置、固定 `*.trycloudflare.com` 域名、自带边缘 TLS | 国内访问质量不稳定；断线频繁；非正式场景不建议 | △ 备选 |
| **⑥ 直接把文件传云端** | 不做隧道，把整个 `exam_system` 部署到 VPS | 想彻底摆脱本机在线依赖 | VPS + 数据迁移 | 本机关机也能用；链路最短 | 需迁移数据库、解决 Windows→Linux 差异、备份责任上云 | ✗ 本次不做 |

### 推荐选择

**主选：方案 ④「云服务器反向代理 + 方案 ③ SSH 反向隧道」组合。**

- 架构：家外用户 → `https://你的域名` → VPS 上的 Nginx（TLS + 限流 + 白名单）→ SSH 反向隧道 → `127.0.0.1:8000` → Flask
- 理由：
  1. 本机在 CGNAT 后且无路由器权限，①②④中的隧道类方案是唯一可行族；
  2. 本机已装 `ssh`，**不需要在本机安装任何新软件**就能建立通道，落地阻力最小；
  3. HTTPS 证书、强制跳转、限流、IP 白名单、访问日志全部收敛在 VPS 一处，**本机代码零改动**，符合「先审后改」原则；
  4. 后续如需换成 frp，只需替换隧道段，上层不动。

**降级选择（无 VPS 时）：方案 ② frp 客户端 + 一个便宜的国内穿透服务商。** 适合先跑通、后加固。

**明确不推荐：方案 ①（在本机物理上不可能）。**

## 1.2 VPS 侧配置项（反向代理层）

| 配置名称 | 取值 / 示例值 | 作用 | 适用方案 |
| --- | --- | --- | --- |
| VPS 规格 | 2 vCPU / 1-2 GB / 5 Mbps 带宽 / Ubuntu 22.04 | 跑 Nginx + 隧道监听足够 | ④ |
| VPS 公网 IP | 自动分配即可（无需 Elastic IP） | 对外唯一入口 | ④ |
| 安全组入方向 | `22/tcp` 限源 IP、`80/tcp` 全开、`443/tcp` 全开、`127.0.0.1:18000` 不开放 | 云厂商第一层防火墙 | ④ |
| `ufw` 规则 | 同上，另 `ufw default deny incoming` | 主机第二层防火墙 | ④ |
| 域名 | `exam.example.com` | 家外用户的固定入口 | ②④⑤ |
| 域名解析 A 记录 | 指向 VPS 公网 IP | DNS 生效后即可访问 | ④ |
| 备案 | **必须**。中国大陆 VPS 用 80/443 绑定域名需 ICP 备案 | 不备案只能用非标准端口或被拦 | ④（大陆节点） |
| 反代监听端口 | `127.0.0.1:18000`（**仅本地**） | SSH 隧道 `-R` 目标端口，绝不可对外 | ③+④ |
| 隧道 sshd 配置 | `GatewayPorts clientspecified`（若需对外） | 决定 `-R` 端口能否绑 0.0.0.0；本方案绑 127.0.0.1 就不需要 | ③ |
| Nginx `server_name` | `exam.example.com` | 唯一虚拟主机 | ④ |
| Nginx 证书路径 | `/etc/letsencrypt/live/exam.example.com/fullchain.pem` + `privkey.pem` | TLS 终止 | ④ |
| 证书签发方式 | `certbot --nginx -d exam.example.com`（Let's Encrypt HTTP-01） | 免费、90 天、自动续期 | ④ |
| 自动续期定时器 | `certbot renew --timer`（systemd timer） | 免手工续 | ④ |
| 强制 HTTP→HTTPS | `return 301 https://$host$request_uri;` | 防明文提交密码/令牌 | ④ |
| HSTS | `add_header Strict-Transport-Security "max-age=31536000" always;` | 降级攻击防护 | ④ |
| 反代上游 | `proxy_pass http://127.0.0.1:18000;` | 回源到隧道监听 | ③+④ |
| 上游连接超时 | `proxy_connect_timeout 10s;` | 隧道断开时快速失败而非挂死 | ④ |
| 读超时 | `proxy_read_timeout 120s;`（考试心跳/交卷请求较长） | 避免长请求被掐 | ④ |
| 客户端最大体 | `client_max_body_size 4m;` | 大于 Flask `MAX_CONTENT_LENGTH=2MB` | ④ |
| 真实 IP 透传 | `proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;`<br>`proxy_set_header X-Real-IP $remote_addr;`<br>`proxy_set_header X-Forwarded-Proto $scheme;` | **必配**。`app.py` 的 `client_ip()` 读 `X-Forwarded-For`，不配则所有审计日志 IP 都变成 `127.0.0.1` | ④ |
| 反代层限流（登录） | `limit_req_zone $binary_remote_addr zone=login:10m rate=10r/m;`<br>在 `location = /api/auth/login` 上 `limit_req zone=login burst=5 nodelay;` | 补应用层「仅按账号限流」的缺口（防止换个账号无限试） | ④ |
| 反代层限流（全站） | `zone=global:10m rate=60r/s;` + `limit_conn_zone $binary_remote_addr zone=conn:10m;`<br>`limit_conn conn 20;` | 防刷静态大文件（`qa.html` 22MB、`cc-home.html` 32MB）耗带宽 | ④ |
| 来源 IP 白名单 | `allow 1.2.3.4; deny all;`（放在最前） | 若只有少量家外固定 IP | ④ |
| Basic Auth 兜底 | `auth_basic "Restricted"; auth_basic_user_file /etc/nginx/.htpasswd;` | 应用鉴权之外的第二道门 | ④ |
| 访问日志 | `access_log /var/log/nginx/exam.access.log combined;`<br>`log_format` 加 `$request_time` `$upstream_response_time` | 审计、定位慢请求 | ④ |
| 日志轮转 | `/etc/logrotate.d/nginx` 默认已配 | 防磁盘写满 | ④ |
| 兜底监控 | `caddy`/`uptime-kuma` 每分钟探 `https://…/api/health` | 通道断了要有人知道 | ④ |

## 1.4 隧道配置项（SSH 反向隧道）

| 配置名称 | 取值 / 示例值 | 作用 |
| --- | --- | --- |
| VPS 上的 sshd | `GatewayPorts clientspecified`、`AllowTcpForwarding yes` | 允许 `-R` 建监听 |
| 隧道命令 | `ssh -NT -o ServerAliveInterval=30 -o ServerAliveCountMax=3 -o ExitOnForwardFailure=yes -R 18000:127.0.0.1:8000 examer@VPS_IP` | 建立 `VPS:18000 → 本机:8000` |
| `-N -T` | 不执行远程命令、不分配终端 | 纯转发 |
| `ServerAliveInterval=30` | 30 秒心跳 | NAT 超时前保活 |
| `ServerAliveCountMax=3` | 连续 3 次无响应即断 | 快速发现死链 |
| `ExitOnForwardFailure=yes` | 端口占用时直接失败退出 | 让守护脚本能感知并重试 |
| 守护方式 | Windows：**任务计划程序**（`ONLOGON` 或 `ONSTART`，需本机策略允许；本机 `schtasks` 曾被禁用 → 改用 `启动文件夹` 放一个 `.cmd` 循环重连脚本） | 断线自动重连 |
| 隧道专用账号 | `examer`，**只给 shell=nologin**，`authorized_keys` 限定 `command="echo tunnel"` 与 `permitopen`/`permitlisten="127.0.0.1:18000"` | 防止隧道账号被拿去干别的 |
| `authorized_keys` 选项 | `restrict,port-forwarding,permitlisten="127.0.0.1:18000" ssh-ed25519 AAAA…` | 即使密钥泄露也只能开这一个本地端口 |
| 若改用 frp | `frpc.toml`：`serverAddr=VPS`、`serverPort=7000`、`auth.token=…`、`[[proxies]] type="tcp" localIP="127.0.0.1" localPort=8000 remotePort=18000` | 功能等价，换成 frp 时的对应配置 |

# 第二部分 · 实施步骤

> 每步标注前提条件与验证方式。**建议先在 VPS 上全部打通、再切本机监听。**

## 阶段 A · 云端准备（前提：有一个能登录的 VPS + 一个域名）

### 第 1 步　确认网络前提
- **前提**：你能 SSH 登录 VPS。
- **操作**：
  ```bash
  # 1) 确认出口是否为 CGNAT（在本机执行）
  curl -s ipinfo.io/json | grep -E '"ip"|"org"'
  # 2) 确认本机是否有独立公网 IPv4：对比「路由器 WAN 口 IP」与「上面查到的出口 IP」
  #    不一致 → CGNAT，方案①直接放弃
  ```
- **验证**：能连上 VPS；本机内网 IP 为 `10.20.30.40`。

### 第 2 步　VPS 基础加固
- **前提**：第 1 步通过。
- **操作**：
  ```bash
  adduser examer                       # 隧道专用账号
  ufw default deny incoming
  ufw allow 22/tcp
  ufw allow 80,443/tcp
  ufw enable
  ```
  同时在**云厂商安全组**同步放行 `22/80/443`（两道都要做）。
- **验证**：
  ```bash
  ufw status verbose
  ss -lntp            # 确认只有 22/80/443 在监听 0.0.0.0
  curl -I http://127.0.0.1            # 应无响应（还没起服务）
  ```
  从**家外手机 4G**（不是同一 Wi-Fi）访问 `http://VPS_IP`：80 应超时或关闭（说明没意外裸奔）。

### 第 3 步　配置 SSH 反向隧道端口
- **前提**：第 2 步通过。
- **操作**：编辑 `/etc/ssh/sshd_config`，确保：
  ```
  GatewayPorts clientspecified
  AllowTcpForwarding yes
  ```
  ```bash
  systemctl restart ssh
  ```
- **验证**：
  ```bash
  ssh -NT -R 18000:127.0.0.1:8000 examer@VPS_IP &
  ss -lntp | grep 18000     # 应显示 127.0.0.1:18000
  curl -s http://127.0.0.1:18000/api/health | head -c 200
  ```
  期望看到 `{"ok":true,"service":"exam-system",…}`。

### 第 4 步　签发证书 + 写 Nginx 反代
- **前提**：第 3 步通过；域名 A 记录已指向 VPS；**大陆 VPS 已完成 ICP 备案**。
- **操作**：
  ```bash
  apt install -y nginx certbot python3-certbot-nginx
  certbot --nginx -d exam.example.com --agree-tos -m you@example.com --no-eff-email
  ```
  写入 `/etc/nginx/sites-available/exam.conf`：
  ```nginx
  # ---- 限流区 ----
  limit_req_zone $binary_remote_addr zone=login:10m rate=10r/m;
  limit_req_zone $binary_remote_addr zone=global:10m rate=60r/s;
  limit_conn_zone $binary_remote_addr zone=conn:10m;

  server {
      listen 80;
      server_name exam.example.com;
      return 301 https://$host$request_uri;
  }

  server {
      listen 443 ssl http2;
      server_name exam.example.com;

      ssl_certificate     /etc/letsencrypt/live/exam.example.com/fullchain.pem;
      ssl_certificate_key /etc/letsencrypt/live/exam.example.com/privkey.pem;
      ssl_protocols TLSv1.2 TLSv1.3;
      ssl_session_cache shared:SSL:10m;

      add_header Strict-Transport-Security "max-age=31536000" always;
      add_header X-Content-Type-Options nosniff always;
      server_tokens off;
      client_max_body_size 4m;

      # ---- 可选：来源 IP 白名单（放在最前，命中即放行）----
      # allow 1.2.3.4; deny all;

      # ---- 可选：应用层之外的第二道门 ----
      # auth_basic "Restricted";
      # auth_basic_user_file /etc/nginx/.htpasswd;

      access_log /var/log/nginx/exam.access.log combined buffer=32k flush=5s;
      error_log  /var/log/nginx/exam.error.log warn;

      location / {
  ```

# 第三部分 · 安全注意事项

## A. 认证与会话

1. **初始密码形同虚设 —— 这是本方案最大的单点风险。**
   当前全员初始密码 = **姓名逐字拼音首字母**（孙皓宇→`LWH`、周晓静→`ZXJ`），且 2026-10-09 后 `must_change=0`，登录即可用。
   这在局域网是可接受的便利；**放到公网 = 系统对全网敞开**。攻击者拿到名册（或用工号规律）就能逐个撞库。
   **必须做**：公网上线前，`python app/init_db.py --reset-pwd` 重置全员工号密码并置 `must_change=1`，或通过管理员后台「首登强制改密」开启；首登新密码 ≥8 位、字母+数字。
   **验证**：随机抽 3 个账号用初始密码在公网入口登录 → 应被强制跳转改密页。

2. **单点登录（SSO）与「家外多设备」冲突。**
   系统已实现「新登录挤掉旧登录」，且正在考试中的考生会被豁免。公网后家外用户更可能在手机+电脑之间切换，**被挤下线会引发误操作丢分**。
   **建议**：公网场景考虑放宽为「同时 2 个会话」，或在登录响应 `kicked_old_session` 时给前端明确提示。

3. **应用层限流只按账号，不按 IP。**
   `app.py` 的 `_fail_key = account|ip` 与 `recent_fail_count`（**刻意只按账号**）——设计目的是避免 NAT 下同事被连坐。
   但公网暴露后，攻击者可以**一个 IP 轮换 53 个工号**，每个账号各试 5 次 = 265 次尝试，完全不触发锁定。
   **必须做**：在 Nginx 加 `limit_req` 按 IP 限流（第 1.2 节已配 `zone=login rate=10r/m`）。

4. **令牌有效期**：`EXAM_TOKEN_TTL_DAYS` 默认 7 天。公网建议改 2 天，降低令牌泄露后的可用窗口。

5. **会话 Cookie 属性**：有 HTTPS 后应确认 `Secure` + `HttpOnly` + 合适的 `SameSite`。当前 `SameSite` 在 http 下会退化为 `Lax`（代码注释已说明），走 HTTPS 后才能正确下发 `None`。

## B. 网络与传输

6. **只让 VPS 能访问本机端口。**
   若保留 `EXAM_HOST=0.0.0.0`（为了局域网手机访问），务必加 Windows 防火墙规则限制来源网段：
   ```bat
   netsh advfirewall firewall add rule name="Exam8000-LAN" dir=in action=allow protocol=TCP localport=8000 remoteip=10.20.30.0/24,fe80::/10
   ```
   更稳妥的是改 `EXAM_HOST=127.0.0.1`，让隧道从内部回连，**根本不监听网卡**。

7. **VPS 的 `18000` 端口绝不能对外。**
   `GatewayPorts clientspecified` 一旦配错（写成 `yes`），`18000` 会绑到 `0.0.0.0`，等于在 VPS 上开了一个**无 TLS、无鉴权**的后门端口——任何人都能绕过 Nginx 直接读接口。
   **检查**：`ss -lntp | grep 18000` 必须显示 `127.0.0.1:18000`。这是每次改配置后都要复验的项。

8. **强制 HTTPS + HSTS。**
   明文下 Bearer 令牌与工号密码等同裸奔。Nginx 的 301 与 HSTS 头都要有；HSTS 上线后**无法在浏览器端撤回**，确认域名长期可用再设。

9. **`X-Forwarded-For` 必须正确透传。**
   不配的后果不只是日志难看：`app.py` 的 `client_ip()` 会把所有请求记成 `127.0.0.1`，**登录爆破的溯源、限流的 IP 维度、切屏日志的证据链全部失效**——而 `focus_events` 的 IP 是考试违规取证的关键字段。
   **另外**：`X-Forwarded-For` 可被客户端伪造。Nginx 用 `$proxy_add_x_forwarded_for`（追加而非覆盖）是正确做法，但若要在应用层做 IP 白名单，必须改为 `$remote_addr` 或在 Nginx 层先清空该头再设置。

10. **协议与端口**：
    - 本方案全是 **TCP**，无 UDP 需求；
    - 反代侧 `proxy_http_version 1.1` + `Connection ""` 以启用 keepalive（否则每请求重建连接，隧道带宽浪费）；
    - `client_max_body_size 4m` 必须 **大于** Flask 的 `MAX_CONTENT_LENGTH = 2MB`，否则大上传会被反代先拒（表现为 413 而非应用层提示）。

## C. 应用与数据

11. **静态文件暴露面必须逐项回归。**
    系统已实现扩展名白名单 + 拒绝 `.`/`_` 开头 + 拒绝 `exam_system/` 前缀。这是**内网时代的安全边界，公网时代是生死线**——一旦漏了 `.db`，53 人的成绩、题库（含正确答案）、`.secret_key` 会直接公开。
    **每次改动静态路由后都要重跑第 7 步的探测清单。**

12. **CORS `Access-Control-Allow-Origin: *` 应按域收紧。**
    当前 `/api/*` 全开 `*`（`app.py` 786-790 行），是为兼容「前端 `file://` + 后端局域网 IP」的权宜之计。公网下这等于**允许任意网站的脚本读取你接口的响应**。虽有 Bearer 令牌兜底，但 `/api/health` 是免鉴权的——会泄露数据库绝对路径、用户数、题库数、版本号、`secret_source`。
    **建议**：改为 `EXAM_CORS_ORIGIN=https://exam.example.com`，同时 `/api/health` 对外隐藏 `db.path`，`/api/netinfo` 加白名单或直接关闭（它会回显本机所有内网 IP）。

13. **CSP `frame-ancestors` 要跟着域名走。**
    默认白名单是 `'self' http://127.0.0.1:* http://localhost:* http://[::1]:*` + 本机局域网 IP。**换成域名访问时若父页不同源，会直接白屏**。上线后必须设 `EXAM_FRAME_ANCESTORS='self' https://exam.example.com`。
    **绝对不要**设 `EXAM_ALLOW_FILE_PARENT=1`——它会在 CSP 末尾追加 `*`，让**任意站点**都能 iframe 嵌入本系统，是教科书级的点击劫持配置（历史上正是这个值留下的 P1 缺陷）。

14. **数据备份与可恢复性。**
    SQLite 单文件，`backups/` 目录 + `manage.bat` 已有备份能力。公网后建议：
    - 每日自动备份到**另一台机器或对象存储**，不要只留在本机同一磁盘；
    - 恢复演练要真做过一次（把备份还原到干净目录跑起来），否则备份只是安慰剂。

15. **合规与单位规定（这条比技术更重要）。**
    当前出口 IP 属中国联通广州、网关搜索域 `smartont.net`——**这是单位网络**。把承载真实人员信息的考核系统暴露到公网，很可能违反：
    - 单位网络与信息安全规定（未报批的内网服务外联）；
    - 《个人信息保护法》（姓名、工号、成绩、班组属个人信息，跨网络提供需告知与授权）；
    - 公司对员工数据的存储边界要求。
    **强烈建议**：先向 IT/信息化部门报批，或至少改用**最小暴露面**的方案（例如只在家外用户确有需要时开 VPN/专线接入，而不是开公网 Web）。
    这不是技术问题，是**你的职业风险**。

## D. 攻击面与运营

16. **端口扫描暴露**：VPS 的 80/443 必然被全网扫描（Shodan、 Censys 几分钟内收录）。**不要用非标准端口指望「隐身」**——扫的是全端口且现在已无成本。真正的防线是：TLS + 限流 + 鉴权 + 隐藏版本信息（`server_tokens off`）。

17. **DDoS 与带宽滥用**：家庭上行带宽通常 30-100 Mbps，且是**上传/下行不对称**——被刷时是你的上传被打满，家里所有人同时掉线。VPS 侧限流 + 云厂商的流量包/带宽封顶是唯一有效防线。**不要**把 VPS 的 22 端口密码登录对全网开放。

18. **隧道断线的静默风险**：SSH 隧道断掉后，家外用户看到的是 502 而不是明确提示。必须配监控：VPS 上每分钟探测 `https://exam.example.com/api/health`，不通就告警（Uptime Kuma / 自建 cron + 邮件/企业微信）。**「服务静默死亡」比「服务明确报错」危险得多。**

19. **日志审计**：
    - Nginx `access_log` + `logrotate`（防写满磁盘导致服务异常）；
    - 已有 `login_log` / `audit_log` / `focus_events` 三张表是优势，**公网后要定期看**：异常 IP、异地登录、凌晨的密集失败；
    - 考试系统的 `focus_events`（切屏日志）是违规取证依据，IP 字段必须真实（见第 9 条）。

20. **凭据管理**：
    - `data/.secret_key` 权限 0600，且**不在任何 Git 仓库里**；
    - SSH 隧道用**密钥**不用密码，`authorized_keys` 用 `restrict` + `permitlisten` 限定它只能开 `127.0.0.1:18000`；
    - frp 的 `auth.token` 若使用，强度 ≥32 字符随机；
    - 所有凭据**不要**写进本方案文档或提交到仓库——本清单里的域名/IP/账号请按你实际情况替换。

21. **更新与依赖**：
    - Flask 会提示「内置服务器非生产环境」——本方案已通过 Nginx 隔离，且可选 waitress（`EXAM_THREADS`），可接受；
    - `requirements.txt` 里的包保持可离线安装（项目已有 `wheels/` 目录，这是好设计，别破坏）；
    - 定期 `pip list --outdated` 看安全补丁，但**升级前必跑 `smoke_test.py` + `assign_test.py` 全量回归**（基线 109 + 72）。

22. **优雅停机与灰度**：先只对 1-2 个家外用户开放（IP 白名单），观察一周（登录失败率、切屏误判率、带宽占用）后再放开。反向代理的 `location /` 前面加一行 `allow` 就能秒切范围。

```
本机（10.20.30.40，CGNAT 出口 203.0.113.55，无公网 IPv4）
  └─ exam_system  EXAM_HOST=127.0.0.1  EXAM_PORT=8000  明文 HTTP（隧道已加密）
     └─ /api/* 鉴权 + CSRF + 登录锁定(5次/10min→锁15min)
```

**三句话说清为什么这么选**：
CGNAT 让「端口映射」物理上不可能 → 必须由内向外主动建隧道；
本机已装 `ssh` → 用反向隧道零安装成本；
HTTPS/限流/白名单/日志全部收敛到 VPS → **本机业务代码几乎不用改**，改动面最小、可回滚。
