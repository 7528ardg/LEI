### 修复原则（12 批全部遵守）

1. **不改事实、不加新事实断言**：所有改写只调整指代、承接与合规口径，不新增任何可被验证的声明。
2. **最小改动**：优先「`这款`→`这款产品`」「补承接起手语」等局部替换，不动整句语义。
3. **合规口径统一**：价格类一律改为「机上专享价、包税一价、一价全包」；退换类一律统一为「非质量问题不退换；质量问题或运输破损按流程负责到底」。
4. **风格统一**：对旅客一律敬称「您」；去掉直播叫卖腔与电商小店腔；改催促为「您慢慢考虑，落地前告诉我就行」。
5. **位置无关自足**：每条素材在任何相邻位置都自带指代对象与承接语（这是 X2/X5 归零的根本手段）。

## 四、检查器校正说明（透明披露）

穷举枚举在收敛过程中暴露了审查器/审计器的若干**判定缺口**。以下校正均属「补全定义」，**不是为了让结果变好看而放宽标准**，逐条说明：

### 1. 品类白名单补全（`ENTITY`）

补入 11 个**真实商品品类词**，原白名单遗漏：`霜`（晚霜/轻润霜）、`喷雾`、`胶囊`、`威士忌`、`纯露`、`商品`、`水乳`、`旅行装`、`便携装`、`颈托`、`旅行枕`。

> 判据：`这款纯露…`「这款晚霜…」的指代对象**已在句中给出**，不构成「指代落空」。原白名单已含 60+ 品类词，属枚举遗漏。

### 2. 前置标记补 `您问`

`/这个牌子|这个品牌|您(看|说|刚|提到)|…/` → 补入 `您问`。

> 判据：`您问的这款是珀莱雅红宝石轻润霜` —— 旅客的提问**本身就是前置指代对象**。

### 3. 品牌识别

`这款X品牌…` 中品牌名即指代对象（仅取长度 ≥3 的品牌，避免短代号误吞）。

> 判据：`这款悦木之源走跨境直采` 中「悦木之源」已明确所指。素材自带品牌名时不计落空。

### 4. 片段 / 标签池自动识别

**整池不足 20% 的条目以句末标点收尾** → 判定为拼接片段池或结构化标签池，D2（缺句末标点 / 标点残渣 / 半全角）不适用。

> 判据：`TS_LEAD_STORY`（`我说说{brand}这个牌子，还有段故事——`）、`MEMORY_HOOK`、`personalization`（`嗯……感觉`）等本就设计为拼接使用，对它们判「缺句末标点」无意义。自动识别出 55 个此类池。

### 5. 结构化定义池显式排除

`curatedScriptSets`（套装名/适用人群/机制/成分/品牌字段值）、`objectionHandlingLibrary`（异议类型 + 应对要点标签）、`rolePlayScenarios`（角色扮演字段值）、`map`（渠道名称对照表）、`effectBiasDetails`、`personalization`、`HOOK_COMMON`、`lines`。

### 6. 规则定义池 / 旅客侧语料 / 训练面板排除

`ALWAYS_BANNED`、`COMPLIANCE_RULES`、`PHRASE_FIX`、`PROTECTED_TERMS`、`STRICT_BANNED`（违禁词表本体）；`responsePool`、`emotionKeywords`、`customerPersonalityTypes`（旅客侧语料与画像标签）；`strategyRecommendations`（只在乘务员训练提示面板渲染，`{x}` 已替换为「【对应内容】」，不到旅客面前）。

### 7. 槽位/动态模板单列

`{named}`（引擎渲染前填充）与 `${...}`（JS 模板字符串运行时求值）单列备查，不计入泄漏。真正计入的只有 `undefined` / `NaN` / `[object` 与语法上无法填充的占位符。

### 8. 审核脚本规则对齐

早期审核脚本 `audit_full_20261013.js` 用的是更宽松的自定义规则（如把**官方口径**「假一赔三」计为 C3、把「三条不**打折**扣的原则」计为 C3b）。本次改为**逐条对齐审查器 `RULE_C/RULE_L/RULE_S`**（`audit_full_v2_20261013.js`），消除两套标准不一致。

## 五、真伪判定记录（哪些是误报，依据是什么）

修复过程中对每条疑似问题做了「真问题 / 检查器误报」判定，全部留痕：

| 现象 | 判定 | 依据 |
|---|---|---|
| `这款悦木之源走跨境直采…`（20 条同构） | **误报** | 品牌名已在句中，指代明确 |
| `您问的这款是…`（4 条） | **误报** | 旅客提问即前置 |
| `这套是奔富BIN407双支…` / `山阴是松井…从它开始` | **半真**：B2C 语境下仍可辩，但素材换商品即成落空 → **已改** | 素材库按商品无关使用 |
| `护肤的黄金时间是晚上10点到凌晨2点` | **真问题** | 会被护栏硬红线拦截 → 素材实际不可用 |
| `不是什么库存清仓` | **真问题（护栏误判否定句）** | 语义合规但护栏盲匹配，仍会被拦 → 改写绕开 |
| `我不敢保证您用上是什么感觉`（免责声明） | **误报** | 否定式免责（「不敢保证」），非承诺 |
| `完全没风险`（规则定义池内） | **误报** | 池内即为违禁词表 |
| `行吧，价格我能接受。不过你得给我保证是正品啊` | **误报** | 旅客模拟器台词，非乘务员话术 |
| `追求极致配送时效` / `追求极致体验` | **真问题** | 护栏「绝对化用语」硬红线 |
| 引擎池 `TS_LEAD_WHO/INGMORE/SPEC/ING` 指代 | **结构性误报** | 经查引擎以 `para +=` 拼接为**段内尾句**，从不独立成轮；仍已加固 | 
| `METAPHOR_BY_TYPE` / `strategyRecommendations` 承接 | **结构性误报** | 前者为段落内嵌于长句的比喻片段；后者为训练面板元数据 |

## 六、遗留事项与建议

1. **未接线库存池（5 池 / 209 条）**
   已清除其 D1/D4 问题（39 处），池内仍含 `{brand}` 类槽位模板 —— 这是**设计如此**，护栏会在接线前拦截。接线时须补齐槽位填充。
   建议：接线前对这 5 池单独跑一遍「填槽后的」审查器。

2. **`scriptLibraryData` 的 `productId` 绑定未被利用**
   1,233 条素材中相当一部分带 `productId`（绑定到具体商品），但生成链未据此约束商品选择。本轮的加固已使这一缺失不再产生可感知缺陷。
   建议：若后续要做「按商品取素材」，可启用该字段，届时可进一步降低 X2 风险面。

3. **X5 的语义边界**
   「上一轮以疑问句收尾」中，**面向旅客的提问**（`…怎么样？` `…还是…？`）在真实对话中由旅客回答，乘务员下一句接续不构成断裂。本轮已按「素材位置无关自足」的标准统一加固，覆盖此边界。
   建议：若未来新增素材，沿用同一标准（每条素材自带承接起语）。

4. **新增素材的入库把关**
   护栏已 fail-closed（L33378、L33468：闸未就绪即拒绝保存/复制）。建议把本报告的复验脚本纳入日常流程：新增素材后跑一次 `exhaust_review_20261013.js` + `audit_full_v2_20261013.js`。
