## 二、已修正的引擎缺陷（3 类）

### 修正 1（P0）· 洗护发品类过渡句池完全缺失

**问题**：`TYPE_TRANS` 过渡表共 37 个键，但 `haircare`（洗发水/护发素/护发精油/染发）**一个键都没有**。  
任何含洗护发产品的组合，必然回落到通用兜底句「刚才那款在护肤序列里管好了它那一步」——对洗护发完全文不对题。

**实测证据**：500 套校验中 14 处「缺承接过渡句」，其中 **12 处涉洗护发**（86%）。

**修正**：补齐 14 个 haircare 过渡键，覆盖与全部 6 个大类型的互转：

| 过渡方向                                          | 修正后效果          |
| --------------------------------------------- | -------------- |
| `haircare\|haircare`                          | 洗护发内部接力（清洁→养护） |
| `skincare\|haircare` / `haircare\|skincare`   | 护肤与洗护发互转       |
| `haircare\|makeup` / `makeup\|haircare`       | 洗护与彩妆互转        |
| `haircare\|fragrance` / `fragrance\|haircare` | 洗护与香氛互转        |
| `haircare\|health` / `health\|haircare`       | 外在与内调互转        |
| `haircare\|alcohol` / `alcohol\|haircare`     | 洗护与酒类互转        |
| `haircare\|souvenir` / `souvenir\|haircare`   | 洗护与纪念品互转       |

两处引擎副本（`beautySceneEngine` + `talkShowEngine`）**同步修正**，避免风格分裂。

### 3.4 五道闸门明细

| # | 闸门       | 作用                                                      |
| - | -------- | ------------------------------------------------------- |
| 1 | 绝对价格区间   | 拦截 `price < 5` 或 `> 9999`（含 0 元、价格倒置）                   |
| 2 | 品类价格区间   | 按 `CAT_PRICE_BANDS` 校验（精华 30~~6000、香水 100~~6000 等 21 类） |
| 3 | 同规格参考带   | 与该规格现有价比对，允许 0.55×~1.8× 浮动                              |
| 4 | 产品整体参考带  | 无同规格数据时，退化为全产品 min×0.25 ~ max×2.5                       |
| 5 | **来源守卫** | 价格数字必须真实出现在搜索文本中，且排除 `$`/`NT$`/`US$` 外币                 |

> 第 5 道是防编造的核心：它不依赖模型自觉，而是**确定性比对字符串**。  
> 代码注释已记录该设计的由来——实测发现模型会把提示词里的参考价冒充「来自搜索结果」。

### 3.5 价格来源与不确定性标注

| 价格类型   | 数量          | 来源                                    | 时效         | 确定性                         |
| ------ | ----------- | ------------------------------------- | ---------- | --------------------------- |
| 竞品参考价  | 27 款 / 94 条 | **人工联网快照**（非实时接口）                     | 2026-09-15 | ⚠️ 一个月前快照，且部分标注「沿用上期数据」     |
| AI 更新价 | 运行时         | Firecrawl/Tavily 实时搜索 → GLM 抽取 → 五道闸门 | 点击更新当时     | ✅ 可溯源（`source` 字段标注第几条搜索结果） |
| 自有产品价格 | 351 条字段，全部 `null` | 产品库 `products[]` **已加 `price` 字段，待业务录入** | — | ⚠️ 暂无数据 |

**本轮新增两项价格安全能力**（实现细节见第九节）：

- **竞品价过期提醒（P1）**：任一价格距今天数 ≥30 或不可解析 → 卡片头标黄「⚠ 价格待刷新」，价格行加黄框 + 黄色提示。内置 2026-09-15 快照距今 27 天，尚未满 30 天阈值，当前 UI 不标黄；一旦满 30 天将自动标黄。
- **价格搜索第三通道（P2）**：Firecrawl/Tavily 双实时源均失败时，回退至该竞品已存真实参考价（本地快照），**绝不编造**；UI 明确区分「🤖 AI 更新价格 / 📦 本地快照价格」，并加黄色警告框。

**必须明确告知的不确定性**：

1. **自有商品价格当前仍无法输出**。`products[]` 共 351 款，`price` 字段已加但**全部为 `null`**。  
   话术里的「机上专享价」「包税含邮」仍是**机制描述**，不是具体金额。  
   500 套话术中含具体数字价格的：**0 套** —— 符合引擎设计边界（不承诺价格）。  
   **基础设施已就绪**：录入真实价后，话术会自动在 5/8/10 分钟档输出「【价格】机上专享价约 ¥X，含关税与运费一价全包。」；`null` 或无字段则不输出（有价才报、无价不编造，已通过探针验证）。
2. **竞品价格是快照，不是实时价**。内置数据标注 2026-09-15，且部分条目标注「沿用上期数据」  
   （即当时未联网到新价）。用于对外报价前**必须先点一次「AI 更新」**；满 30 天后 UI 会自动标黄提醒。
3. **AI 更新失败 → 本地快照兜底**。双实时源均失败时回退已存真实参考价（不编造、不空白），  
   但 UI 会标注「📦 本地快照」，务必核对来源；若该竞品连一条参考价都没有，则明确报错「本地无历史参考价」。
4. **搜索源可用性是外生风险**。Firecrawl/Tavily 均为 keyless 免费额度，  
   额度耗尽或网络异常时回退快照。实测当前两个源均正常（HTTP 200）。

### 9.2 P1 · 竞品价过期提醒（Task #6）

### 9.3 P2 · 价格搜索第三通道（Task #7）
