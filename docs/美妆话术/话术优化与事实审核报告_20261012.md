## 二、根因分析：为什么会出现"牛头不对马嘴"

### 2.1 核心缺陷：功效细分池是死代码

原 `feelFor()` 的取用顺序是：

```js
const typePool = TYPE_FEEL[bt];      // ① 先按大类型取（护肤/彩妆/香水/酒/保健/纪念品）
if(typePool){ return pick(typePool); }
// ↓ 下面这段从未执行
for(const key in FEELING){          // ② 按 coreBenefits 细分（保湿/抗老/美白/控油…）
  if(key.split('|').some(k => hay.indexOf(k) >= 0)) return pick(FEELING[key]);
}
```

`TYPE_FEEL` 对 7 个大类型**全部存在**，所以 ① 必然命中，② 的按功效细分池**永远不会执行**。
结果就是：不管产品实际功效是什么，一律套用该大类型的通用感受。

### 2.2 实测证据（优化前）

| 产品 | 实际 coreBenefits | 被注入的话术 | 问题性质 |
|---|---|---|---|
| 圣罗兰小金条口红 | 丝滑显色、持久不掉色、轻薄不拔干、复古红调、高级质感 | 「味道是那种低调的清新，不冲人」 | **香水的话给了口红** |
| 普拉达 B101 唇膏 | 丝滑显色、赤棕优雅、轻薄贴唇 | 「妆感是那种高级的**哑光**感，不用费劲**遮瑕**」 | **口红说遮瑕/哑光** |
| 雅诗兰黛 DW 粉底液 | 超长持妆、高遮瑕力、轻薄透气、控油不拔干 | 「像给身体开了个**小马达**」「**免疫**」 | **保健品话给了粉底液** |
| 奔富赤霞珠 | 深宝石红色泽、黑果橡木香气、单宁顺滑 | 「像给身体存笔小钱，日积月累」「**蓬松**」 | **保健/洗护发话给了红酒** |
| 娇韵诗紧致眼霜 | 淡化眼周细纹、紧致眼周、改善松弛 | 「像给**脸**开了个补水循环」 | **补水（面部）给了眼霜** |
| 纪梵希四宫格散粉 | 均匀肤色、柔化油光、轻透柔光 | 「涂完**嘴唇**不干，是润的」 | **口红时刻给了散粉** |

**影响面**：共 **173 款产品**（占全库 49%）被注入过至少一条与其真实功能无关的表述。

### 2.3 附带根因

- **`_catAlias` 把 `'彩妆'` 映射到 `'口红'`**：17 款彩妆（粉底/气垫/遮瑕/散粉/修容/腮红/眼影/口红）共用口红场景。
- **合规清洗误伤真实专名**：`STRICT_BANNED` 含"干细胞"，会把赫莲娜真实成分「海洋堇干细胞精萃」删成不存在的「海洋堇精萃」——**删掉的是事实本身**。

## 三、优化内容

### 3.1 架构修正（事实一致性守卫）

在引擎内新增 `CLAIM_TERMS` 断言词表 + `groundingOf()` / `isGrounded()` / `groundedPick()` 三件套，
并把 `feelFor / metaphorFor / sceneMoment / sceneFeel / pickOpening / MEMORY_HOOK / MOMENT_ALT / SCENE_PICTURE / valueLineFor`
**九个素材注入点全部接入守卫**。

规则：候选句若含有该产品数据（name/brand/category/tale/description/coreBenefits/targetSkinTypes/tags/keyIngredients）中
**找不到依据的功效断言词**，一律跳过；全池都不合格时退回最保守表述。**绝不编造，也绝不因噎废食删掉真实专名**。

同时把取用顺序改为「**先按 coreBenefits 命中细分池，再退回大类型池**」，并限定
FEELING（护肤语境池）**只对护肤/洗护发生效**——彩妆、香水、酒、保健、纪念品一律走各自品类池。

### 3.2 表达优化（逻辑 / 说服力 / 共鸣）

| 优化项 | 原状 | 改后 |
|---|---|---|
| `BENEFIT_LEADS` | 14 条全是"说白了/讲白了/换句话"同义反复 | 改为承载**因果与转译**的连接词：「落到您身上就是」「它凭什么做到」「对您来说意味着」「您可能最关心的是」 |
| `HOOK_COMMON` | 18 条 | 扩至 39 条，新增 21 条**去推销感**表达：「我不催您」「不合适您直接跳过，我不会觉得可惜」「买不买都在这儿」「不打算买也欢迎您听」 |
| `TYPE_FEEL.makeup` | 5 条 | 扩至 22 条，覆盖上妆/补妆/挑色/手法等真实场景 |
| `MAKEUP_SUBTYPE_FEEL`（新建） | 无 | 口红/粉底/遮瑕/定妆/腮红/眼影/修容/眉笔/睫毛 各 3~5 条独立感受 |
| `MAKEUP_SUBTYPE_SCENE`（新建） | 无 | 9 个子品类各自的"使用时刻"，替代原先一律套用口红场景 |
| 硬伤清理 | — | 烧酒场景里的英文 `friends` →「朋友」；保健品感受「身体会记住**你的**用心」→「您的用心」 |

### 3.3 数据层修正

| 问题 | 处理 |
|---|---|
| 3 组同名产品（`DHC橄榄卸妆油` 120/100ml、`伊丽莎白雅顿绿茶蜜滴身体霜`、`欧缇丽手部及指甲修护霜` 30ml/75ml vs 30ml）规格/成分不同 | 标题自动追加规格副标：`『DHC橄榄卸妆油（120ml/200ml）』`，消除"重复推荐"歧义。**未改动产品数据本身**（属商品库治理范畴，需业务确认） |
| `【肤质】`标签 | 改为**数据驱动**：仅当 targetSkinTypes 过半为肤质属性才用【肤质】，否则用【适合人群】 |

## 六、遗留问题与建议（需业务决策）

| 编号 | 问题 | 影响 | 建议 |
|---|---|---|---|
| **1** | `products[]` 中 3 组同名条目规格/成分不同 | 话术已加后缀消歧，但**销售统计与库存仍会混淆** | 由商品运营确认：合并为一条，或按规格拆分为不同 SKU 并改名 |
| **2** | `informationInquiry` 预置问答中的规格与产品记录不一致（如某酒款问答写"500ml"、产品 volume 为"720ml/1.8L"） | 旅客可能听到与自己下单规格不符的描述 | 逐条对齐问答与产品记录 |
| **3** | 全部 351 款 `price` 仍为 `null` | 话术无法报真实价格 | 业务录入机上价后自动生效（有价才报、无价不编造） |
| **4** | 整体重复率约 68% | 集中在开场/收尾/品质段落开场白（段内重复 88~93%） | 下轮扩充这三类开场白池 |
