零、先说三处勘误 竞品报告是对着外部写的；这一份是对着源码写的，结论有出入

我把竞品报告里的每一项都拿去源码里核对了一遍，有 3 项判断需要修正——如果直接按上一份报告排期会白做。
勘误 1 · M1 置信度徽标「待做」→ 实际已完成
源码 qa.html:11507 已有完整实现（__QA_ANSWER_TOOLS_20260921__ 内），三档文案齐全，低置信原文为：
「当前知识库没有直接命中，下面是相近条目或引导。建议换个关键词，或切换到对应库再问。」
→ 所以「查无依据显式化」这件事基本已经做到了，剩下的是「低置信时主动告诉用户该去哪个库」这一层引导。M1 降级为「收尾项」，不再占用一个 P0 名额。
勘误 2 · M3 原文定位跳转「中成本可做」→ 实际做不到，必须降级
· manual.html（163 KB）没有任何章节级 DOM 锚点——它的 id 全是 kw / rules / view-scores 这类 UI 元素，不是手册正文段落。它是一个查询界面，不是手册全文。
· 它只读一个 URL 参数 ?from=，不支持 ?kw= 预填搜索词。
· 现有 jumpTo()（qa.html:2748）走 postMessage({type:'spring-switch', module})，只传模块名、不传参数；壳层 index.html 只认这一个字段。
→ 拆成两案：案 A（批 2，纯 qa 侧，小成本）点出处展开「出处详情小卡」；案 B（批 3，跨 3 文件，含壳层）才是一键带词跳到手册查询页。原报告把它写成一次改动，成本低估了。
勘误 3 · M4 版本时效「需给条目逐条建版本映射」→ 不需要，成本大幅低于预估
实测 src 字段是章节号而非文件名，例如 管理手册 4.35 酒精测试管理规定 / CCM 7.10.4 / 手册 6.7.9.3.4——也就是已经标到章节了。
更关键的是：CBT 题库里本来就带版本考题，例如 现行有效的《客舱乘务员手册》版本号为 01/10，解析里写「现行有效版本为 01/10，修订日期 2026-03-02」。
→ 说明版本信息是库级的、不是条目级的。做一张六库版本注册表就够了，不必给几千条目逐条打标。这一项从「中-高成本」降到低成本，可以提到批 1。
顺带捡到一个质量问题（不在原清单里）：QA_QUIZ_POOL 的解析字段 e 里有大量 OCR 残留，形如 ========== PAGE 41 ==========。这些残串会原样显示在「❌ 正确答案…」的解析里。 清洗成本极低（一次正则 + 幂等补丁），建议并入批 1 顺带做掉，编号 Q1。

键名上限结构说明

为什么整卷成绩要新开一个键：qa_train_records_v1 每条只有 {at, correct, total, score}，现有成绩趋势曲线依赖这个形状。 往里塞 mode / byChapter 会让旧记录与新记录形状不一致，趋势曲线和已有断言都可能错。 新键更安全，代价只是「趋势曲线只反映随堂练习」。若之后要让整卷也进趋势，再单开一次迁移。

  • kbStrong(hits) 与 hits[0].s —— 已有包装捕获了 last = {top,n,src,pool}，置信度/出处详情/缺口记录共用这一份数据，不要再包一层
  • qaTrainQuizHtml 渲染路径 + qaGradeQuiz 判分 —— 错题重练与整卷模式都复用它，只是传参与后续处理不同
  • setQaSource(pool) / jumpTo(mod) —— 切库引导与跨模块跳转

批 2 风险点 这几处最容易踩

  • R2 新增形参必须在函数签名末尾。现有调用点有 4 处（:9746 / :9819 / :9827 / :9858），其中 :9746 来自 params（语音/命令触发）。只加末尾形参可保证 4 处调用全部不受影响。
  • R6 分享在 APK 内必失败。navigator.share 需要 HTTPS 安全上下文（PWA 侧才有），APK 是 https://cabin.local 自定义 scheme，必须准备好下载降级，否则点了没反应。（此类坑本模块已有先例：WebView 未实现 onJsConfirm 导致 confirm 静默返回 false）
  • R4 与 V1 抢同一行 DOM。两件事都改「🔎 来源」行，建议合并为一次改动做，别分两次碰同一处字符串，否则第二次的精确匹配会失配。
  • R5 不要做成「AI 写报告」。一旦引入自由生成就是外发，违背口径；模板 + 拼接足够覆盖 JAL 那个场景的核心价值（结构化、不遗漏、可复制）。

六、每批的构建与验证流程 照这个顺序走，别跳步

  1. 写 patcher：Python 脚本读写一律 newline=''；注入用 strip→replay 幂等块；块头写清楚需求与回归命令。
  2. 跑 patcher：改的是既有块（mypanel / answer_tools）就先跑对应的原 patcher，再跑新 patcher。
  3. 补断言：把本计划里的验收断言写进 _check_needles.py 或对应 _verify_*.js；新块守卫串必须本补丁特有。
  4. 构建：_build_all → _build_hosted → _check_needles。前台跑别超过 120s，超时会被 SIGTERM 掐（卡在 APK 实测段属正常）。
  5. 浏览器实测：playwright 用 channel:'msedge'；liveDocs（src≠about:blank）才是活跃指标；本地存储键用 localStorage 直接读校。
  6. 落盘安全：脚本用「固定临时名覆盖写 + 不删除」。沙箱单轮 os.remove 累计到 50 会静默死、无 traceback。
  7. APK 打包：等你明确通知再打，不自动跑。
